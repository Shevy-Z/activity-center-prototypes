# 活动中心项目梳理

## 1. 项目是什么

这是 DFN 售后/保客活动中心的产品原型与历史证据包，当前范围不包含售前/潜客活动中心。

活动中心负责配置活动、参与对象和准入规则，关联卡券或积分奖励，维护门店、车型、人群和活动互斥关系，并将活动规则同步给卡券中心、新商城等下游系统。用户侧覆盖领券、抽奖、分享、二维码参与和领券结果；运营侧覆盖活动创建、发布、报表、来源追踪和二次运营。

核心业务链路可以概括为：

`配置活动与准入 → 关联卡券/奖励 → 发布并同步下游 → 用户参与/领取 → 核销或履约 → 报表与运营追踪`

其中，活动中心决定“谁能参加、参加什么活动、关联什么奖励以及活动之间如何互斥”；卡券中心负责卡券模板和实例；新商城等渠道负责展示、下单或核销规则执行。跨系统字段和责任边界仍有部分待确认项。

## 3. 推荐入口与内容地图

### 最新 Axure：活动中心 1106

入口：`../活动中心1106/index.html`

- 共 114 个原型页面，覆盖活动创建、活动列表、准入配置、组合活动、互斥关系、增发任务、活动报表、SA 报表和 C 端活动。
- 同时包含后台统一推送、用户行为触发、卡券激活/失效、续保、取送车、专属福利等存量业务逻辑。
- 后续相关设计应先对照该版本的页面层级、字段位置、状态转换和交互方式；专题 Git 原型用于补充较新的局部方案。
- 原型中标注“待更新”“需求已变更”或“×”的历史方案不能直接作为现行规则，仍需结合页面标注和需求证据判断。

### 最近专题：组合活动与保客准入

入口：`02_GitHub原型/活动中心/combo-activity-tiered-claim-prototype/V008_20260910_5170372/原始文件/index.html`

- `combo-activity/`：4 组共 12 个页面状态，覆盖政策页、登录、抽奖、领券结果和升级回流，并附 3 张业务流程图。
- `retention-activity/`：保客活动创建时的准入联动与候选卡券过滤。
- 活动中心后端负责按号码级准入过滤；BIMC 新、维修保养新场景还要求卡券核销方式恰为线上核销。

### P0 主专题

入口：`02_GitHub原型/活动中心/P0-活动中心原型中心/index.html`

活动中心重点看：

- P0-05：活动积分发放方案。
- P0-06-01 / P0-06-02：SA 动态二维码、后台配置、来源报表与用户聚合页。
- P0-08：活动关联奖励。
- P0-09：一店一码一键领取。
- P0-10：行为上报。
- P0-11：活动与卡券互斥/叠加。
- P0-12：活动适用门店及 Excel 覆盖导入。
- P0-13：组合活动。

### 员工分享与二次运营

入口：`02_GitHub原型/活动中心/version-12-prototype-act-cou/V003_20260827_fc5b2da/离线预览/index.html`

- 后台配置默认海报背景、标题、副标题和二维码引导语。
- 员工端沿用既有角色、分享权限、海报编辑和分享流程。
- 客户/卡券记录支持来源追踪、再次分享和 7 天“即将到期”Tag。
- Push、短信、服务助手消息通知不在这一版原型范围内。

### 历史 Axure 基线

入口：`03_历史原型基线/活动中心/index.html`

主要覆盖活动创建、保客活动、组合活动、互斥关系、后台统一推送、用户行为触发、卡券激活/失效、活动统计、取送车和续保等存量设计。该版本优先级低于 `活动中心1106`，仅用于版本对照和追溯来源，不代表当前线上实现。

## 6. 接手后的优先动作

1. 向研发、测试和业务负责人复核上表状态，特别是“开发中”是否已经进入测试或上线。
2. 先收口组合活动的三个边界：分级领取、成功页跳转、保客准入过滤，避免按三个原型重复建设或漏范围。
3. 明确活动结算与活动补贴的责任系统和数据合同，这是当前材料中最明显的需求缺口。
4. 为 SA 来源归因、员工分享和二次运营补齐数据口径、权限、脱敏和验收指标。
5. 原型评审、研发完成、测试通过和生产上线分别留证；不要仅凭“存在原型”更新为已完成。
