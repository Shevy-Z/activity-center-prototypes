门店全员活动分享｜评审导航返回评审入口

建议评审顺序

先用 Mermaid 时序图统一全链路，再确认后台“谁能分享、分享什么”，最后逐页评审员工生成、客户执行、券实例追踪和再次分享。

第一组：Mermaid 业务时序

  1. 打开 Mermaid 业务时序图：从创建活动到客户再次分享。
  2. 覆盖普通活动、组合活动、二维码、准入、互斥、一键参与与自动抽奖。
  3. 展示最后成功执行触点、参与记录、子执行、券实例和核销状态的关联。
  4. 页面仅保留 Mermaid 图，并提供完整源码查看与复制。

第二组：后台授权

  1. 普通活动创建：适用门店、允许分享角色、准入表达。
  2. 组合活动列表：父级门店/角色与子活动。
  3. 活动分享配置：只维护投放对象和状态。
  4. 二维码参数：固定时长、长期有效、默认值。

第三组：员工生成

  1. 员工选择活动：角色与唯一门店过滤。
  2. 我的二维码：本人记录、详情和再次保存。
  3. 分享海报：系统模板、自定义上传、文案和头像。
  4. 我的分享数据：活动、卡券与客户入口。

第四组：客户执行

  1. 未绑车聚合页：组合活动卡券整体隐藏。
  2. 已绑车聚合页：多子活动命中全部展示。
  3. 切换 VIN、互斥切换、一键参与、自动抽奖和不回跳升级流程均沿用原版。
  4. 客户公开层只显示来源门店和员工姓名，不展示角色或二维码有效期。

第五组：客户级追踪

  1. 后台客户维度：按来源账号 + oneID聚合上线后券实例。
  2. 券实例明细：参与记录、组合子执行与券实例关联。
  3. 员工客户列表：本人客户查询与状态汇总。
  4. 客户详情与再次分享：逐券查看后回到普通分享流程。
边界：客户卡券只纳入功能上线后数据；“已过期”券保留追踪，真正“已失效”券不展示、不统计；再次分享不绑定客户、不建原券到新券的特殊链路；所有页面数据为 Mock。
